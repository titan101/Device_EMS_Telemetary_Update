Every step writes its record to runs/<run>/status.json before the next one starts (re-read, overlay, tmp + replace). A second fix skips confirmed and compliant boxes; --redo repeats them. Ctrl-C never starts a queued device; an open session is recorded as outcome unknown.

Two rules the whole flow rests on

Nothing reaches a device unless asked twiceCLI: --live opens sessions, and --yes is what runs instead of printing the plan. Console: type LIVE to arm, tick "for real" on the action, and the ISE fix shows its plan first. jlogin's exit code is never trusted -- every transcript gets a verdict.
Every fix file carries its own exact rollbackNot an inversion of the new lines: the device's own pre-change lines, restored object by object. The timer is the first line of defence; the rollback block is for after a confirm.
